= Acessos
:navtitle: Acessos

Esta página é referência, não exercício — volte a ela sempre que precisar de um
endereço ou de uma senha. Nada aqui está escrito à mão: **tudo é descoberto do
seu cluster no momento em que você roda o comando.**

[IMPORTANT]
====
Não existe tabela de senhas neste guia, e a ausência é deliberada: senha em
documento é senha vazada, e o cluster é efêmero — a cada provisionamento muda
hostname e muda segredo. O que existe é o comando que descobre.
====

== A folha completa

Um comando, e sai tudo o que o cluster tem: cada console com URL, usuário e
senha.

[source,role="execute"]
----
bash ~/rhcl/scripts/acessos.sh
----

Variações úteis:

[cols="1,3"]
|===
| `--mask` | senhas ocultas — use se estiver **gravando a tela** ou apresentando
| `--all` | inclui o que não faz parte do roteiro (ODF, AAP, e o que mais existir)
| `--md` | saída em Markdown, para colar em outro lugar
|===

[source,role="execute"]
----
bash ~/rhcl/scripts/acessos.sh --mask
----

A folha lista só o que **existe** no cluster: o script diz onde procurar, e quem
não estiver lá simplesmente não aparece. Se um console sumir da lista, ele não
foi instalado — não é falha do script.

== Os endereços, um a um

Se quiser só um endereço, cada um sai de um comando:

[cols="1,2,2"]
|===
| Onde | Comando | Usado em

| Este guia
| `oc get route showroom -n showroom -o jsonpath='{.spec.host}'`
| o dia inteiro

| Console do OpenShift
| `oc whoami --show-console`
| 2.3, 2.4, 3.3, 3.4

| A aplicação do laboratório
| `echo https://bookinfo.$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')/productpage`
| 1.1, 2.5, 2.7

| Developer Hub
| `oc get route -A -l app.kubernetes.io/name=developer-hub -o jsonpath='{.items[0].spec.host}'`
| 1.1, 3.6

| Argo CD
| `oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.spec.host}'`
| 1.2

| GitLab
| `oc get route -A \| grep -i gitlab`
| 1.1, 1.6

| Grafana
| `oc get route -A -l app.kubernetes.io/name=grafana -o jsonpath='{.items[0].spec.host}'`
| 3.5

| ACS (Central)
| `oc get route central -n stackrox -o jsonpath='{.spec.host}'`
| 1.4

| Quay
| `oc get route -A \| grep -i quay`
| 1.4, 1.5
|===

[NOTE]
====
O console do OpenShift **não abre nas abas ao lado**: ele responde
`X-Frame-Options: deny` e recusa ser embutido. Abra numa janela separada — é por
isso que os módulos mandam rodar `oc whoami --show-console` em vez de apontar
para uma aba.
====

== Sua identidade no cluster

[source,role="execute"]
----
oc whoami && oc whoami --show-server
----

No módulo xref:16-t1-rbac.adoc[1.6] você vai descobrir que, neste cluster, essa
identidade pode tudo — e que é justamente por isso que aquele módulo usa
impersonação para mostrar o que uma função *limitada* poderia fazer.

== O que fazer quando um endereço não responde

Antes de investigar, pergunte se o serviço existe:

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh diagnostica
----

Sem número, ele olha só as camadas de plataforma e diz o que está de pé. Um
`503` numa aba quase sempre é serviço que ainda não subiu, e não rota quebrada.
