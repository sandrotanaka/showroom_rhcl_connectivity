= Acessos
:navtitle: Acessos

Esta página é referência, não exercício — volte a ela sempre que precisar de um
endereço ou de uma senha. Nada aqui está escrito à mão: **tudo é descoberto do
seu cluster no momento em que você roda o comando.**

[IMPORTANT]
====
Não existe tabela de senhas neste guia, e a ausência é deliberada: senha em
documento é senha vazada, e o cluster é efêmero — a cada provisionamento muda
hostname e muda segredo. O que existe é o comando que descobre.
====

== Primeiro: entrar no cluster

Quase tudo nesta página depende disto. **Antes do `oc login` você não é você** —
o terminal fala com o cluster pela ServiceAccount do Showroom, que só enxerga o
próprio namespace. Um `acessos.sh` rodado antes do login volta praticamente
vazio, e não é defeito: é a identidade errada perguntando.

[source,role="execute",subs="attributes+"]
----
oc login -u {user} -p {password} {openshift_api_url} --insecure-skip-tls-verify
----

[NOTE]
====
Se o comando acima aparecer com `%ATTR_NOT_SET%` no lugar do usuário e da senha,
este ambiente subiu sem as credenciais do formulário. Elas estão na **tela do
serviço na RHDP**, junto do link deste laboratório — copie de lá.
====

. Confirme quem você virou:
+
[source,role="execute"]
----
oc whoami && oc whoami --show-server
----

Enquanto a resposta for `system:serviceaccount:showroom:showroom`, o login não
aconteceu.

== De onde vem a senha de cada um

Elas **não vêm todas do mesmo lugar**, e é isso que trava quem procura uma senha
só:

[cols="1,1,2"]
|===
| Console | Usuário | De onde sai a senha

| *OpenShift* e a API
| o do laboratório
| **da tela do serviço na RHDP** — o único que não está no cluster. O provedor é o Keycloak, e a senha vive fora daqui.

| *Keycloak (RHBK)*
| `admin`
| `oc extract secret/keycloak-initial-admin -n keycloak --to=-`

| *Argo CD*
| `admin`
| Secret no cluster — a folha abaixo resolve

| *Grafana*
| `admin`
| Secret no cluster — a folha abaixo resolve

| *GitLab*
| `root`
| Secret no cluster. As quatro personas do golden path (`globex-travel`, `initech-voyages`, `acme-trips`, `plat-eng`) têm senha própria, também na folha.

| *Developer Hub*
| **uma persona do GitLab**
| não tem senha própria — é o login unificado.
|===

== A folha completa, resolvida do cluster

Depois do login, um comando devolve tudo com usuário e senha:

[source,role="execute"]
----
bash ~/rhcl/scripts/acessos.sh
----

[cols="1,3"]
|===
| `--mask` | senhas ocultas — use se estiver **gravando a tela**
| `--all` | inclui o que está fora do roteiro
| `--md` | saída em Markdown
|===

[WARNING]
====
Rodado **antes** do `oc login`, este comando devolve quase nada — a
ServiceAccount não lê Route nem Secret fora do namespace dela, e a API aparece
como um IP interno. Não é o script quebrado; é a identidade errada.
====

== Perdeu o lugar no roteiro

O progresso fica no seu `$HOME`, que é volume persistente: sobrevive a
recarregar a página, reconectar o terminal e reiniciar o pod.

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh status
----

Mostra os 20 módulos, marca os que já passaram e aponta onde você está. Para
seguir dali:

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh proximo
----

Ele verifica o módulo atual. Passou, registra e anuncia o próximo; **não passou,
não avança** — chama o diagnóstico e você continua no mesmo módulo.

[NOTE]
====
Um módulo só entra na lista quando a *verificação* passa, nunca por ter sido
aberto. O `status` responde "o que eu fiz", e não "onde eu cliquei".
====

== O que fazer quando um endereço não responde

Antes de investigar, pergunte se o serviço existe:

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh diagnostica
----

Sem número, ele olha só as camadas de plataforma e diz o que está de pé. Um
`503` numa aba quase sempre é serviço que ainda não subiu, e não rota quebrada.
