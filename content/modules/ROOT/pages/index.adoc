= Red Hat Connectivity Link — do gateway à plataforma de API
:navtitle: Boas-vindas

Bem-vindo. Nas próximas duas horas você vai pegar uma API que já existe — sem
tocar em uma linha do código dela — e transformá-la em um **produto** com três
planos comerciais, cota por contrato, número de negócio no Grafana e uma
fronteira interna que a chave de API não abre.

Este workshop é autoguiado. Você tem um cluster OpenShift só seu, e cada módulo
termina com uma verificação que confirma, na sua máquina, que o passo funcionou.

== Para quem é

Duas cadeiras, e o workshop precisa das duas:

[cols="1,3"]
|===
| *Engenharia de Plataforma*
| Onde a policy mora, quem vence quando duas se sobrepõem, e o que a plataforma
  garante sem pedir nada ao time de aplicação.

| *Desenvolvimento*
| Como um serviço novo nasce já com policy de borda, plano comercial e fronteira
  leste-oeste — sem abrir um ticket para a plataforma.
|===

A tese que os sete módulos defendem é uma só: **o Connectivity Link é uma
plataforma de API, não um gateway**. O Módulo 6 é onde as duas cadeiras se
encontram.

== O que você precisa saber antes

* `oc` na linha de comando — `get`, `apply`, `logs`. Nada além disso.
* Noção de YAML. Você vai ler bastante e editar pouco.
* Não é necessário conhecer Istio, Envoy, Kuadrant ou Gateway API. O workshop
  apresenta cada um quando ele aparece.
