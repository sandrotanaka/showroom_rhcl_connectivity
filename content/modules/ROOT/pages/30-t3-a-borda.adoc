= 3.1 A borda muda de dono
:navtitle: 3.1 A borda muda de dono

*Tempo: 18 minutos*

[NOTE]
.Quem executa este módulo
====
*`plat-eng`* — engenharia de plataforma. A credencial e os links estão em
xref:03-acessos.adoc[Acessos]; é a mesma para OpenShift, GitLab e Developer Hub.

Um parceiro não conseguiria — e dá para conferir **sem trocar de usuário**:

[source,role="execute"]
----
oc auth can-i delete httproutes -n bookinfo --as=plat-eng
oc auth can-i delete httproutes -n bookinfo --as=acme-trips
----

`yes` e `no`. A permissão vem da função, não da pessoa.
====

A aplicação entra hoje pelo gateway que veio com ela. Comercial quer vender
acesso — e para isso a borda precisa mudar de dono.

== Objetivos

* Distinguir o gateway da aplicação do gateway governado pela plataforma.
* Mover as rotas de um para o outro, resolvendo o conflito de caminho.
* Explicar por que dois gateways no mesmo cluster não é redundância.

== Contexto: dois gateways, dois donos

[cols="1,3"]
|===
| `bookinfo-gateway` | veio com a amostra, vive no namespace dela, classe `istio`. É o gateway **da aplicação**.
| `prod-web` | vive em `ingress-gateway`, é governado pelo Connectivity Link e carrega policies de escopo de gateway. É o gateway **da plataforma**.
|===

. Veja os dois:
+
[source,role="execute"]
----
oc get gateway -A
----

== Exercício 1: as duas fronteiras convivem

A aplicação continua respondendo pelo gateway dela, e a camada de plataforma
sobe **ao lado**, em outro hostname. Nada é apagado.

. Veja as duas rotas do upstream:
+
[source,role="execute"]
----
oc get httproute -n bookinfo
oc get route -n bookinfo
----

[IMPORTANT]
====
Não tente apagar a `HTTPRoute` do upstream para "liberar" o caminho. Duas
razões, e as duas foram medidas:

* o `ApplicationSet` a **recria em segundos** — o que está no Git é o que vale;
* e o hostname `bookinfo.<domínio>` é servido por uma `Route` do OpenShift que
  aponta para o gateway da amostra. A decisão acontece na **borda**, antes de
  qualquer policy: o pedido nunca chegaria ao `prod-web`.

Comparar as duas lado a lado é demonstração melhor do que trocar uma pela outra.
====

== Exercício 2: as rotas novas

A camada de Connectivity Link da amostra existe pronta, **fora** do
`kustomization.yaml` — a amostra sobe primeiro como Istio puro, de propósito.

. Veja o que ela traz:
+
[source,role="execute"]
----
ls ~/rhcl/samples/bookinfo/rhcl/
----

. Aplique só as duas rotas, substituindo o domínio:
+
[source,role="execute"]
----
D=$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')
for f in 20-httproute-ui.yaml 21-httproute-api.yaml; do
  sed "s|__DOMAIN__|$D|g" ~/rhcl/samples/bookinfo/rhcl/$f | oc apply -f -
done
----

[WARNING]
====
`oc apply -k` não serve aqui: as duas rotas trazem `__DOMAIN__`. Aplicar o
diretório direto publicaria o literal no hostname.
====

== Exercício 3: o que acontece agora

. Chame a UI pelo novo caminho:
+
[source,role="execute"]
----
D=$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')
curl -sk -o /dev/null -w 'UI pelo prod-web -> %{http_code}\n' "https://bookinfo-rhcl.$D/productpage"
----

. Você deve ver **`403`**.

Não é erro seu. É a plataforma funcionando exatamente como foi configurada — e
o próximo módulo é sobre por quê.

[NOTE]
====
`403`, e não `401`: a recusa é de **autorização**, não de autenticação. O
gateway não está dizendo *"quem é você?"* — está dizendo *"não decidi que você
pode"*. A diferença aparece no corpo da resposta, que traz a mensagem do
operador do gateway.
====

== Verificação

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh verifica 31
----

.Se falhar
[%collapsible]
====
Antes de improvisar, peca o diagnostico — ele olha as camadas de baixo e
imprime sintoma, causa provável e comando:

[source,role="execute"]
----
bash ~/workshop/scripts/workshop.sh diagnostica 31
----

*A UI respondeu `200`?* A rota do upstream ainda existe e está atendendo. Confira:

[source,role="execute"]
----
oc get httproute -n bookinfo
----

*A rota nova não aparece no `prod-web`?* Confira se ela foi aceita pelo gateway:

[source,role="execute"]
----
oc get httproute bookinfo-ui -n bookinfo -o jsonpath='{.status.parents[*].conditions[*].message}{"\n"}'
----
====

== O que isso significa

Dois gateways não são redundância — são **duas fronteiras com donos
diferentes**. O da aplicação pertence ao time que a escreveu; o da plataforma
pertence a quem responde por quem entra, quanto passa e quanto isso custa.

Mover a rota de um para o outro é o momento em que uma aplicação vira um
**produto**. E o `403` que você acabou de receber é a primeira prova de que a
mudança de dono foi real.
