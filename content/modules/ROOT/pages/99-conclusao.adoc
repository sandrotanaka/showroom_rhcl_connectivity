= Conclusão
:navtitle: Conclusão

*Tempo: 6 minutos*

== O que você fez

Em duas horas, uma API que já existia virou um produto com três planos, cota por
contrato, número de negócio no painel e uma fronteira interna que a chave de API
não abre.

[cols="1,3"]
|===
| Módulo 1 | A aplicação recusa sem ter código de autenticação
| Módulo 2 | Vocabulário comercial virou configuração — um label e uma policy
| Módulo 3 | Quando duas policies se sobrepõem, o status nomeia quem venceu
| Módulo 4 | A dimensão de negócio entra na métrica na borda, por policy
| Módulo 5 | A decisão de policy é rastreável com as ferramentas que já existiam
| Módulo 6 | Um serviço novo não consegue nascer sem policy, plano e fronteira
| Módulo 7 | A chave de API abre a porta da rua, não o cofre
|===

== O que você não fez

Não alterou uma linha da aplicação. Confira, se quiser:

[source,role="execute"]
----
oc get deploy -n travel-agency -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.template.spec.containers[0].image}{"\n"}{end}'
----

As mesmas imagens do começo. É isso que separa uma plataforma de API de uma
biblioteca de autenticação: **a capacidade não foi adicionada ao código, foi
adicionada ao caminho**.

== A tese, agora que você mediu cada parte

Um gateway responde *"quem entra"*. Uma plataforma de API responde:

* quem entra — `AuthPolicy`;
* quanto passa, por contrato — `PlanPolicy`;
* quem vence quando duas regras colidem — o campo de status;
* quanto isso vale em dinheiro — `TelemetryPolicy`;
* como o próximo serviço nasce já com tudo isso — o golden path;
* e onde a fronteira continua, depois da borda — Service Mesh.

Os seis primeiros módulos existem para que o sétimo não seja uma promessa.
